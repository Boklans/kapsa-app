# KAPSA — Приватні капсули моментів для друзів та пар

**Слоган:** *Один момент на день. Спільні жарти. Спогади, які залишаються.*

---

## 1. Концепція продукту (Core Loop)

**KAPSA** — це закритий соціальний застосунок для найближчих (компанії друзів 3–8 людей або пари з 2 людей). Замість нескінченного чату, де губляться жарти й фотографії, учасники щодня відкривають одну спільну «Капсулу дня».

### Головні правила механіки:
1. **Два режими кімнати (`room_type`):**
   - `friends` («Банда 🔥» — від 3 до 8 учасників)
   - `couple` («Пара ❤️» — 2 учасники)
2. **Три формати щоденних раундів (`prompt_format`):**
   - **`vote` (Голосування «Хто з нас...?»):** Учасник голосує за одного з учасників кімнати та за бажанням додає короткий коментар *«Чому саме він/вона?»*.
   - **`show` (Покажи момент):** Одне фото «тут і зараз» із коротким підписом.
   - **`answer` (Історія / Питання):** Коротка текстова відповідь до 280 символів.
3. **Чесне розкриття без блокування на одному учаснику:**
   - Доки ти не відповів сам — ти бачиш аватарки тих, хто вже зробив хід (`has_answered = true`), але їхній контент прихований на рівні бази даних (у UI відображається як заблюрена картка із замком).
   - **Щойно ти зробив свій хід** — тобі миттєво відкриваються картки всіх учасників, які вже відповіли!
   - Якщо відповіли всі активні учасники кімнати (`status = 'active'`), або настав серверний час відкриття раунду (`reveal_at`, за замовчуванням 21:00 у часовому поясі кімнати) — капсула дня відкривається повністю для всіх, і фіксується фінальний підсумок голосування.
4. **Золотий фонд (`Pin to Lore ⭐`):**
   - Будь-яку відкриту відповідь, фото або результат голосування можна в один тап зберегти у «Золотий фонд» кімнати (`lore_items`). Це формує накопичувальний «музей» внутрішніх мемів і спогадів компанії з першого дня.

## 2. Архітектура безпеки (Supabase + RLS)

- **Жодних клієнтських обходів блюру:** Приховані відповіді захищені на рівні PostgreSQL RLS та `SECURITY DEFINER` RPC-функцій із фіксованим `search_path = public`.
- **Lazy-генерація раундів (`get_or_create_today_round`):** Раунд на поточну дату (в часовому поясі кімнати `room.timezone`) створюється атомарно та ідемпотентно (`UNIQUE(room_id, round_date)`) при першому зверненні до кімнати або за розкладом.
- **Фільтрація неактивних учасників:** Дострокове відкриття раунду перевіряє кворум лише серед активних учасників (`room_members.status = 'active'`).
- **Захист фото у Supabase Storage:** Приватний бакет `room-media` віддає файли тільки тоді, коли серверна функція `can_reveal_round(round_id, auth.uid())` повертає `true`.

## 3. Структура проєкту (Expo Router + Supabase + Zustand)

```text
kapsa-app/
├── app/
│   ├── _layout.tsx             # Кореневий стек та ініціалізація сесії
│   ├── index.tsx               # Список кімнат користувача + створення / вхід за кодом
│   ├── join/[code].tsx         # Приєднання за інвайт-кодом або deep link
│   └── room/[id]/
│       ├── index.tsx           # Головний екран дня (Питання + Сітка карток + Голосування)
│       └── lore.tsx            # Золотий фонд кімнати (Pin to Lore ⭐)
├── components/
│   ├── PromptCard.tsx          # Картка сьогоднішнього завдання (Vote / Show / Answer)
│   ├── MemberResponseCard.tsx  # Картка учасника (Заблюрена / Очікування / Відкрита + Pin)
│   └── VoteSummaryBanner.tsx   # Банер підсумків голосування (Лідер для друзів / Match для пари)
├── constants/
│   └── colors.ts               # Дизайн-система KAPSA (Dark Mode + неонові акценти)
├── lib/
│   └── supabase.ts             # Клієнт Supabase з AsyncStorage
├── store/
│   ├── authStore.ts            # Сесія та профіль користувача
│   └── roomStore.ts            # Стейт активної кімнати, раунду та Lore
├── types/
│   └── kapsa.ts                # TypeScript-інтерфейси БД та RPC-відповідей
└── supabase/
    └── migrations/
        └── 001_initial_kapsa_schema.sql  # Повна SQL-схема + RLS + RPC + Seed-питання
```
